Authentication Flow

JWT-based multi-tenant authentication with access + refresh token rotation

How Login Works (Step by Step)

1

User enters credentials

Email + Password + Tenant Slug (organization identifier like "demo")

2

Frontend calls POST /auth/login

Sends { email, password, tenantSlug } to backend

3

Backend validates & returns tokens

Returns { user, accessToken, refreshToken }. Access token expires in ~15min, refresh token in ~7 days

4

Tokens stored in localStorage

Zustand auth store saves user + tokens with persistence. isAuthenticated set to true

5

All API calls include Authorization header

Authorization: Bearer {accessToken} added automatically by api-client

6

Token auto-refresh on 401

When access token expires, api-client calls POST /auth/refresh with refreshToken, gets new tokens, retries original request

Chat Widget (Embeddable)

Preact-based chat widget that embeds on any website to capture leads via AI conversations

How to Install

Add this script tag to your website's HTML (before </body>):

<script
  src="https://your-api-domain.com/widget.js"
  data-agent-id="YOUR_AGENT_ID"
  data-api-url="https://your-api-domain.com/api/v1"
  data-position="bottom-right"
></script>

data-agent-id - Get this from Dashboard > AI Agents > select agent > Embed Code tab

How Widget Works (Step by Step)

1

Widget loads on page

Creates/retrieves visitor ID from localStorage. Sends page view tracking to POST /widget/pageview

2

Fetches agent config

Calls GET /widget/config/{agentId} to get: name, welcome message, colors, lead capture fields

3

Visitor clicks chat bubble

Opens chat panel (380x520px). Starts conversation via POST /widget/conversations/start

4

AI responds to messages

Visitor sends message, backend processes with AI (OpenAI/Anthropic) using system prompt + knowledge base. Widget polls every 3 seconds for new messages

5

Lead capture form appears

After 4+ messages, widget shows lead form (name, email, phone). Submits to POST /widget/leads/capture

6

Lead created in dashboard

Lead appears in Leads page with source "widget". Scoring rules evaluate. Workflows trigger if configured

🛡 Security Architecture

Complete security measures applied across Backend (NestJS), Frontend (Next.js), WebSocket, and Infrastructure layers

1 Route Protection & Authorization

All controllers are protected with role-based access control. No endpoint is accessible without proper authentication and role verification.

Controller Before After Fix Allowed Roles
ConversationController ❌ No @Roles ✅ @Roles added ADMINSALES_MANAGERSALESPERSON
DashboardController ❌ No @Roles ✅ @Roles added ADMINSALES_MANAGER
SupportTicket → addNote ❌ No @Roles ✅ @Roles added ADMINSALES_MANAGERSALESPERSON
VIEWER Role Guard ❌ Bypass all GET ✅ Fixed - read-only GET only VIEWER = Read Only

Guard Chain (order matters): AuthGuard → TenantGuard → RolesGuard → ThrottlerGuard. Every request passes through all 4 guards.

2 Rate Limiting (Brute Force Protection)

All auth and public endpoints are rate-limited using @nestjs/throttler to prevent brute force attacks, credential stuffing, and abuse.

Endpoint Method Max Requests Per Window Protection Against
/auth/register POST 5 1 minute Mass account creation
/auth/login POST 10 1 minute Credential brute force
/auth/refresh POST 20 1 minute Token enumeration
/auth/forgot-password POST 3 1 minute Account enumeration
/auth/reset-password POST 5 1 minute Token brute force
/appointments/available-slots GET 20 1 minute Schedule scraping
/appointments/book POST 10 1 minute Slot flooding
Global default ALL 100 1 minute General DDoS

3 Injection Protection

Multiple layers of injection prevention applied across all data entry points.

Attack Type Protection Implementation Files Protected
NoSQL Injection (body) express-mongo-sanitize Strips $ and . from request body/query All endpoints (global middleware)
NoSQL Injection (sortBy) Whitelist validation Only allowed field names: createdAt, name, email, status, score etc. paginate.ts → all paginated APIs
ReDoS (Regex DoS) escapeRegex() utility Escapes .*+?^${}()|[]\ in search input Lead, User, Agent, SupportTicket, KnowledgeBase services
XSS (Cross-Site Scripting) React auto-escaping + CSP header React escapes output; CSP restricts inline scripts All frontend components
Request Validation ValidationPipe whitelist: true, forbidNonWhitelisted: true → strips unknown fields All endpoints (global pipe)
sortOrder validation @IsIn(['asc','desc']) Only asc/desc allowed pagination.dto.ts
Search length limit @MaxLength(100) Prevents giant regex payloads pagination.dto.ts

4 CORS & Origin Security

Component Before After Fix
HTTP CORS (main.ts) Wildcard * allowed in origin list Wildcard filtered out, only exact origins
Development localhost bypass Any http://localhost:* allowed Removed — only configured origins in env
Chat WebSocket CORS origin: '*' CORS_ALLOWED_ORIGINS from env
Notification WebSocket CORS origin: '*' CORS_ALLOWED_ORIGINS from env
Credentials enabled credentials: true on all

Important: Set CORS_ALLOWED_ORIGINS in apps/api/.env to your exact frontend domains (comma-separated). Never use * in production.
